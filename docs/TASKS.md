### T17.1 — безопасная приёмка DOCX, начато 28.10.2026

Самостоятельный подготовительный этап T17: не требует готовности Anonymizer/сравнения/авторизации и не снимает их обязательность для полной T17. Ветка feat/T17-docx-upload-guard поверх документационной ветки T19; изменения парсера/поиска T24–T27 исключены. БД и UI не меняются.

**Цель:** до вызова существующего парсера отказывать небезопасным/неподдерживаемым DOCX и удалять отвергнутый временный файл. Переиспользовать save_upload_file для обоих существующих HTTP-путей, без дублирования правил.

**Границы:** domain — лимиты/решения/типы ошибок без HTTP и файловой системы; application — проверка через порт инспектора; infrastructure — ограниченное чтение ZIP/XML без извлечения на диск; текущий file_reader — композиция, streaming и отображение ошибок в HTTP. Бизнес-проверки наказания и frontend не меняются.

**Лимиты первого этапа:** 512 ZIP-записей; центральный каталог ≤256 КиБ до создания ZipFile; суммарная распаковка ≤100 МиБ, запись ≤20 МиБ, XML ≤8 МиБ; отношение распаковки ≤200; XML-глубина ≤128, суммарные XML-элементы ≤200000. Приём сжатого файла остаётся под существующим UPLOAD_MAX_MB. ZIP64/multipart, шифрование, неподдерживаемое сжатие, traversal/symlink/дубликаты, DTD/entities и macro-enabled пакеты отклоняются. Это ограниченный обычный DOCX, а не проверка отсутствия вредоносного содержимого всех форматов.

**Риски/остаток:** ресурсы PDF/других форматов, общее число файлов/параллельных загрузок, отдельный процесс с принудительным таймаутом, разрешение нестандартных OOXML-пакетов, атомарность/очистка ранее принятых файлов при пакетном импорте общей базы и полный privacy-gate остаются в T17/T18.
